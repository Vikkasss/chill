# Frontend Master Spec

## Назначение

Фронтенд Personal OS — адаптивная React PWA для Mac, iPhone и iPad. Текущая версия `v0.4` включает Planner, Fitness и Nutrition и работает с единым HTTP API под префиксом `/api`.

## Стек и запуск

- React 19 + TypeScript.
- Vite для разработки и production-сборки.
- Nginx раздаёт production-сборку в Docker и проксирует `/api` в FastAPI.
- Service Worker и Web App Manifest обеспечивают устанавливаемую PWA.

Точки входа:

- `src/main.tsx` — запуск React и регистрация Service Worker в production.
- `src/App.tsx` — оболочка и переключение разделов Planner/Fitness/Nutrition.
- `src/api.ts` — единый клиент HTTP API.
- `src/styles.css` — общие стили и адаптивные правила.

## Оболочка и навигация

На широком экране отображается боковое меню. На телефоне используется фиксированная нижняя навигация. Состояние активного раздела хранится локально в `App`; маршрутизация URL в `v0.4` не используется.

Разделы:

- Planner — задачи и сроки.
- Fitness — календарь тренировок и история.
- Nutrition — дневные цели по белку и калориям.

## Planner

Компонент: `src/features/planner/PlannerView.tsx`.

Функции:

- создать задачу с названием, сроком и выбранным цветной иконкой начальным приоритетом;
- увидеть автоматически повышенный приоритет при приближении срока;
- переключить представление «День»/«Список»;
- фильтровать задачи: все, в работе, готово;
- отметить задачу выполненной или вернуть в работу;
- редактировать название, срок и начальный приоритет;
- удалить задачу после подтверждения;
- показать загрузку, пустой список и ошибку с повтором запроса.

Сортировка выполняется бэкендом: незавершённые задачи выше завершённых, затем эффективный приоритет, срок и время создания.

## Fitness

Компонент: `src/features/fitness/FitnessView.tsx`.

Функции:

- увидеть календарь месяца;
- нажать дату и открыть попап;
- сохранить тренировку одним свободным текстом «На что был упор»;
- отметить чекбокс «Креатин принят»;
- открыть занятую дату или карточку истории и изменить тренировку;
- удалить тренировку из попапа редактирования;
- увидеть цветную отметку на датах с тренировками;
- увидеть короткую зелёную полоску под датой, если принят креатин;
- посмотреть упрощённую историю тренировок с подписью и нижней зелёной полоской для креатина.

Старые подробные тренировки остаются совместимыми с API, но подробная форма больше не показывается.

## Nutrition

Компонент: `src/features/nutrition/NutritionView.tsx`.

Функции:

- показать текущие итоги относительно целей 95 г белка и 1850 ккал;
- отобразить первый и второй круг выполнения цели;
- добавить белок и калории без обязательного названия еды;
- посмотреть добавленные значения за все даты в блоке «История» с датой каждой записи;
- отредактировать или удалить ошибочную запись и сразу пересчитать итоги;
- изменить дневные цели в попапе настроек.

## Состояние и обмен данными

Данные не дублируются в браузере: после мутации компонент повторно загружает актуальное состояние API. Поэтому Mac, телефон и планшет видят одну SQLite через общий сервер.

Типы контрактов находятся в `src/types.ts`. Базовый URL API:

- `/api` по умолчанию;
- `VITE_API_URL` может переопределить адрес при отдельном размещении фронта и API.

Vite proxy направляет `/api` на `127.0.0.1:8000` в режиме разработки. Nginx направляет `/api` на Docker-сервис `api:8000` в production.

## PWA и сеть

- Manifest: `public/manifest.webmanifest`.
- Service Worker: `public/sw.js`.
- Service Worker регистрируется только в production-сборке.
- Полноценная офлайн-работа с локальными изменениями пока не реализована.
- Для доступа устройств используется HTTPS Tailscale Serve.

## Адаптивность

Основные контрольные ширины:

- до `760px` — нижняя навигация и одноколоночные Fitness/Nutrition;
- до `520px` — вертикальные панели инструментов и упрощённые формы.

Интерфейс учитывает `safe-area-inset` для iPhone и `prefers-reduced-motion`.

## Проверка

```bash
cd apps/web
npm run build
```
