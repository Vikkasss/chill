# Backend Master Spec

## Назначение

Бэкенд Personal OS — модульный монолит на FastAPI с SQLite. Текущая версия `v0.4` предоставляет API для Planner, Fitness и Nutrition, healthcheck и безопасное резервное копирование работающей базы.

## Запуск приложения

Точка входа: `app/main.py`.

При старте приложение:

1. определяет путь SQLite из `PERSONAL_OS_DB_PATH` или использует `apps/api/data/personal_os.db`;
2. создаёт отсутствующие таблицы и индексы;
3. регистрирует репозитории Planner, Fitness и Nutrition в `app.state`;
4. подключает маршруты модулей.

В Docker база расположена в `/data/personal_os.db`. Каталог `/data` является bind mount папки `data/` проекта, поэтому рабочий файл доступен на Mac как `data/personal_os.db`.

## Слои модуля

Каждый доменный модуль расположен в `app/modules/<module>`:

- `schemas.py` — входные и выходные Pydantic-модели;
- `repository.py` — SQL и преобразование строк SQLite;
- `router.py` — HTTP-маршруты и обработка `404`.

Модули не импортируют таблицы друг друга. Общая инфраструктура ограничена `Database` и FastAPI-приложением.

## Planner API

Базовый путь: `/api/tasks`.

| Метод | Путь | Функция |
| --- | --- | --- |
| `GET` | `/api/tasks` | Получить задачи; фильтры `date` и `completed` |
| `POST` | `/api/tasks` | Создать задачу |
| `PATCH` | `/api/tasks/{id}` | Изменить название, дату или приоритет |
| `PATCH` | `/api/tasks/{id}/completion` | Изменить статус выполнения |
| `DELETE` | `/api/tasks/{id}` | Удалить задачу |

Задача содержит `title`, срок `due_date`, выбранный `base_priority`, вычисленный `priority`, `completed`, временные метки и числовой `id`. Эффективный приоритет повышается до среднего за 3–5 дней и до высокого за 0–2 дня или после просрочки.

## Fitness API

Базовый путь: `/api/workouts`.

| Метод | Путь | Функция |
| --- | --- | --- |
| `GET` | `/api/workouts` | Получить историю тренировок с упражнениями и подходами |
| `POST` | `/api/workouts` | Атомарно создать тренировку, упражнения и подходы |
| `PATCH` | `/api/workouts/{id}` | Изменить текст, дату или отметку креатина |
| `DELETE` | `/api/workouts/{id}` | Удалить тренировку |

Новая упрощённая тренировка содержит дату, текст фокуса в `title` и булеву отметку `creatine_taken`. На одну дату API разрешает только одну тренировку и возвращает `409`, если дата занята. Поля упражнений остаются в контракте для чтения ранее созданных подробных тренировок, но могут быть пустыми.

## Nutrition API

Базовый путь: `/api/nutrition`.

| Метод | Путь | Функция |
| --- | --- | --- |
| `GET` | `/api/nutrition/day?date=YYYY-MM-DD` | Получить цели, итоги и записи дня |
| `GET` | `/api/nutrition/entries` | Получить историю записей за все даты |
| `POST` | `/api/nutrition/entries` | Добавить белок и калории |
| `PUT` | `/api/nutrition/entries/{id}` | Изменить белок и калории записи |
| `DELETE` | `/api/nutrition/entries/{id}` | Удалить запись |
| `PUT` | `/api/nutrition/goals` | Изменить дневные цели |

## Схема данных

### `planner_tasks`

- данные задачи и статус выполнения;
- индекс по `due_date`.

### `fitness_workouts`

- название, дата, заметка, отметка употребления креатина и временные метки;
- обычный индекс и уникальный индекс по `performed_on`, если в существующей базе нет старых дублей.

При старте существующая база автоматически получает колонку `creatine_taken` со значением `false` для старых тренировок. Старые дубли дат не удаляются автоматически; API при этом не позволяет создавать новые дубли.

### `fitness_exercises`

- принадлежность тренировке;
- название и позиция;
- удаляется каскадно вместе с тренировкой.

### `fitness_sets`

- принадлежность упражнению;
- номер подхода, вес и повторы;
- уникальная пара `exercise_id + set_number`;
- удаляется каскадно вместе с упражнением.

### `nutrition_settings`

- единственная строка глобальных целей;
- значения по умолчанию: 95 г белка и 1850 ккал.

### `nutrition_entries`

- дата, количество белка, калории и время создания;
- индекс по дате употребления.

## Резервное копирование

Модуль `app/backup.py` использует SQLite Online Backup API. Он создаёт согласованный снимок даже при запущенном приложении и передаёт файл в stdout.

Корневая команда:

```bash
./scripts/backup-db.sh
```

Снимки сохраняются в `backups/personal_os_YYYYMMDD_HHMMSS.db`. Файлы базы исключены из Git, директория остаётся в репозитории через `.gitkeep`.

Перед восстановлением необходимо остановить запись в API и сохранить отдельный снимок текущей базы. Автоматическое восстановление пока намеренно не реализовано, чтобы исключить случайную потерю данных.

## Docker

- `apps/api/Dockerfile` запускает FastAPI непривилегированным пользователем.
- `compose.yaml` подключает папку проекта `data/` как `/data`, сохраняя базу между перезапусками и делая её доступной локальным SQLite-инструментам.
- API доступен только внутренней Docker-сети.
- Nginx фронтенда является единой внешней точкой входа.

## Ошибки и валидация

- Pydantic возвращает `422` для некорректных входных данных.
- Отсутствующие задачи возвращают `404`.
- Успешное удаление задачи возвращает `204`.
- Необработанные ошибки транзакции приводят к rollback SQLite.

## Проверка

```bash
cd apps/api
.venv/bin/python -m pytest
```

Тесты покрывают жизненный цикл задачи, фильтрацию, создание/редактирование/удаление Fitness и Nutrition, настройку пути базы и резервное копирование.
